# Version sources in toll

Reference for the `create-release` skill. `toll` has no single version
constant; the release identity and the version baked into artifacts come from
different places.

## Sources

- `cmd/toll/main.go` — `var version = "dev"`, passed to
  `fang.WithVersion(version)`. This is the **only** version the CLI prints
  (`toll version <v>`). Nothing overrides it except the linker flag below.
- `nix/packages.nix` — one line to bump:

  ```nix
  version = if self ? rev then "0.1.0-${self.shortRev}" else "0.1.0-dev";
  ```

  It is injected with
  `ldflags = [ "-s" "-w" "-X main.version=${version}" ]` and is also the OCI
  image's internal tag (`tag = version`).
- `nix/web.nix` — two lines to bump:
  - the same `version = if self ? rev …` expression for `packages.web`;
  - `version = "0.1.0+${lib.replaceString "-" "." rev}"` for
    `packages.web-node-modules` (a `+` build-metadata suffix, not `-`).

  Find all three with `grep -rn '0\.1\.0' nix/`.
- `web/package.json` — **no `version` field**; nothing to bump.
- `.github/workflows/release.yml` — on a `v*` tag push the git tag name is used
  verbatim as the GHCR tag, plus `:latest`. Every other run (push to `main`,
  manual) publishes `snapshot-<sha>` only and never moves `:latest`.
- Release notes are generated by **git-cliff** from the commit bodies
  (`cliff.toml` at the repo root); there is no committed `CHANGELOG.md` by
  default (see the `create-release` skill).

## What each build reports (clean git tree)

| Build | Reports |
| --- | --- |
| `go build ./...` / `go run ./cmd/toll` | `dev` (no ldflags) |
| `nix build .#toll` → `./result/bin/toll --version` | `0.1.0-<shortRev>` |
| `nix build .#web` | `0.1.0-<shortRev>` |
| `nix build .#web-node-modules` | `0.1.0+<shortRev>` |
| `nix build .#image` → name:tag | `toll:0.1.0-<shortRev>` |
| `ghcr.io/trfdeer/toll` (CI) | git tag verbatim, e.g. `v0.1.0`, plus `:latest` |

`go install github.com/trfdeer/toll/cmd/toll@v0.1.0` also reports `dev` because
nothing sets the ldflag on that path. The version is never exposed over HTTP —
`/healthz` does not return it.

## Gotchas

- **A dirty tracked tree aborts the hash.** If a tracked file is modified, Nix
  marks the tree dirty, `self ? rev` becomes false, and every version falls back
  to `0.1.0-dev` (with `warning: Git tree … is dirty`). Untracked files do
  **not** count as dirty. CI does a clean `actions/checkout`, so only local
  builds are affected.
- **`go build` says `dev`.** Expected — do not "fix" `main.go`'s default to a
  release number, or every dev build would lie.
- **Keep the `-<shortRev>` suffix.** It is the only full-precision identity of a
  running image; the GHCR tag is the human-facing release name. Producing a bare
  `0.1.0` would require removing the `if self ? rev …` branch and losing
  traceability for all dev builds.
- **The prefix is not the tag.** Nix flakes expose `self.rev` / `self.shortRev`
  but not tags, so a `vX.Y.Z` tag does nothing to the compiled-in `x.y.z`; you
  must edit the literals in the same commit that you tag.

## Verify

Read-only reporter (evaluates Nix attrs and compiles the Go binary; no image
build):

```sh
./.opencode/skills/create-release/scripts/report-versions.sh
```

Confirm the ldflag mechanism without a full Nix build:

```sh
go build -ldflags "-s -w -X main.version=0.1.0-$(git rev-parse --short HEAD)" \
  -o /tmp/toll ./cmd/toll && /tmp/toll --version
```
